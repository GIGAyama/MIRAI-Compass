# **🧭 みらいコンパス**

**「みらいコンパス」は、公立小学校での「自由進度学習」を強力に支援するGoogle Apps Script (GAS) ウェブアプリケーションです。**

子どもたちが自ら学習計画を立て、実行し、振り返るサイクルをデジタル化。先生はリアルタイムで子どもたちの学びを見取り、適切なサポートを行うことができます。GIGAスクール構想の1人1台端末（Chromebook等）での動作に最適化されています。

## **✨ できること**

### **👦 児童の画面 (Student Mode)**

児童はクラスと名前を選んで「スタート」するだけで使えます（パスワードなし）。
画面の下に **4つのタブ**が常に出ていて、そこがすべての入口です。

| タブ | できること |
|---|---|
| **きょう** | いま何をすればいいかを1つだけ大きく提案（計画が空なら「けいかくを たてる」、未完了があれば「つぎは◯◯」、全部終わったら「ふりかえり」）。タスクを押すと「できた！」にでき、ワークシートがあればその場で開きます |
| **けいかく** | 単元の課題を、時間割のコマへ**ドラッグ＆ドロップ**で並べて計画を立てます。自動保存され「ほぞんずみ／ほぞんちゅう」を常時表示 |
| **ポートフォリオ** | 毎時間の「ふりかえり」の積み重ね（あゆみ）と、単元のまとめを書く画面。発揮した力を**レーダーチャート**で可視化します |
| **ひろば** | 友だちが「公開」にしたワークシートの回答を読み、スタンプ（👍💮👀✨）と40文字までのひとことを送れます。読むだけで、書き込みはできません |

そのほか、児童画面には次のものがあります。

* **SOS / しゅうちゅう**: ボタン1つで先生の画面へ状態を知らせます（SOS は先生側でチャイムが鳴り、カードが赤くなります）。
* **みんなの けいかく（ギャラリーウォーク）**: クラス全員の計画を並べて見られます。**はじめは匿名**で、「名前をみる」で表示に切り替わります。
* **じぶんの かだいを つくる（マイタスク）**: 先生の課題以外に、自分で決めた課題を足して計画に入れられます。
* **ふりかえり**: 毎時間、達成度とコメントに加えて、**8つの力**（自己管理・計画性・対話・協力・挑戦・工夫・集中・責任）から発揮したものを選びます。これがレーダーチャートの元になります。
* **自分用タイマー**: カウントアップ／カウントダウンの両方。右下のボタンから開き、ドラッグ（タッチ可）で好きな場所に置けます。
* **先生からの反応がそのまま届く**: 児童画面は **10秒ごと**に状況を、**30秒ごと**に先生のスタンプと授業配信を取りに行きます。スタンプが届くとお祝い演出が出ます。開きっぱなしでもリロード不要です。
* **保存に失敗したら必ず伝える**: 通信が切れたときは、どの保存が失敗したのかを児童にも分かる言葉で知らせます（黙って消えません）。
* **全文ルビ対応**: 児童画面の文言はひらがな・ルビ付きです。拡大も禁止していません。

### **👩‍🏫 先生の画面 (Teacher Mode)**

先生の画面のメニューは「**授業の流れ**」の3フェーズに分かれています。
ビューは7つで、①には名簿を開くボタンが同居します。
どのビューからでも右上の「**印刷**」「**新規単元登録**」が押せます。

| フェーズ | ボタン | できること |
|---|---|---|
| ① じゅんび | **単元設計** | 単元と課題を作る。テンプレート／手動／AIインポートの3通り |
| ① じゅんび | **授業配信** | 「いま何時間目のどの単元か」をクラスへ配信。時間割（1〜6限）のボタンから時刻を入れられます |
| ① じゅんび | **名簿**（モーダル） | 名簿管理を開きます。ビューの切り替えではありません |
| ② 授業中 | **LIVE** | クラス全員のカードが並び、いまの課題と SOS がリアルタイムに見えます（自動更新） |
| ② 授業中 | **座席** | 教室の座席の並びどおりにカードを置いて見守ります。ドラッグで配置を保存（自動更新） |
| ② 授業中 | **進捗一覧** | クラス全員 × 課題の進み具合を表で俯瞰。**セルを押すとその場でスタンプを送れます**（自動更新） |
| ③ みとり・かえす | **添削** | 提出されたワークシートを一覧し、赤ペンとコメントで返却。**AI一括コメント**で全員分の下書きも作れます |
| ③ みとり・かえす | **まとめ** | 児童が書いた単元のまとめを読み、スタンプとコメントを返します（一括保存あり） |

* **はじめかたガイド**: 単元・名簿・配信のどれかが未了のうちは、次にやることが画面上部に出ます。3つとも済むと自動で消えます。
* **単元テンプレート（4種）**: 導入〜まとめまで組み立てずみの単元をワンクリックで作成できます。
  **単元設計の経験がない先生でも、その日から自由進度学習を始められます。**

  | テンプレート | 教科・学年 | 時数 |
  |---|---|---|
  | はじめての自由進度学習 | どの教科でも | 3 |
  | 火事からくらしを守る | 社会・3年 | 8 |
  | 面積 | 算数・4年 | 7 |
  | ふりこの運動 | 理科・5年 | 6 |

* **単元設計（AIアシスト）**: 生成AI（ChatGPT/Gemini）で作った授業案の **JSON を貼り付けて取り込め**ます
  （「新規単元登録」→「AIインポート」タブ）。貼り付け時に不足項目を日本語で具体的に指摘します。
  AI に渡す指示文（プロンプト）は先生が編集・保存できます。タスクの「必修/選択」「実施回」「カテゴリ
  （まなぶ／ふかめる／まとめる）」「先生主導/個別」も編集画面から直接変更できます。
* **ワークシート（作成→配布→回答→添削→ひろば）**: 単元のタスクから、この**アプリ内**でワークシートを
  作成します。**配布のための操作はありません**（作るとそのタスクに自動でひも付きます）。児童はタスクを
  開くとその場で回答（入力＋手書き）・提出でき、先生は赤ペンで添削して返却します。児童が「公開」にした
  回答は「ひろば」で読み合えます。**旧「みらいパスポート」の機能を取り込み、別アプリ・別ログインは不要**です。
* **ワークシート生成 AI（2経路）**: **① Gemini API**（設定→「AI設定（Geminiキー・モデル）」でキー登録）による
  自動生成、**② 手貼り HTML** による作成。API キー未設定でも②で回ります。
  使用する Gemini モデルは設定画面のプルダウンから選択可能（一覧は API から自動取得、
  未設定時は `gemini-2.5-flash`）。ルーブリック（評価規準）も AI で下書きできます。
* **提示モード**: 右上のイーゼル（黒板）アイコンで、電子黒板向けに文字とボタンを大きくして全画面化します。
  **児童の名前ははじめ伏せてあり**、「なまえを出す」で表示します。
* **印刷**: 「まとめ」「進捗一覧」などを紙で配れます（印刷用 CSS でナビ・ボタン・タイマーは出ません）。
* **名簿管理**: Excel/名簿ソフトからの**コピペ登録**、出席番号順の並び、転出児童の非表示（記録は残る）、
  **メールアドレス列（任意）**。メールを入れておくと、同名児童がいても名簿と学習記録が正確に結びつきます。

## **🛠 ファイル構成**

プロジェクトは以下のファイルで構成されています。

GAS に置くファイルは **11 個**です（`.gs` 2 個 ＋ `.html` 9 個）。
スプレッドシートのコピーで配る場合は、この 11 個がコピーの中に入っています。

```
/
├── code.gs             # サーバーサイドロジック (DB操作、認可、APIエンドポイント、スキーマ点検)
├── Gemini.gs           # ⚠️ 正本のコピー：Gemini API 呼び出し（再試行つき）。貼り忘れるとAI生成だけが落ちる
├── index.html          # エントリーポイント (ライブラリ読み込み、ファイル結合)
├── css.html            # スタイルシート (デザイン定義)
├── js_core.html        # 共通ロジック (設定、データ管理、通信、初期設定・設定画面)
├── js_student.html     # 児童用画面ロジック
├── js_teacher.html     # 先生用画面ロジック
├── js_worksheet.html   # ワークシート（作成・回答・添削）オーバーレイ ※統合で追加
│
├── vendor_css.html     # ⚠️ 生成物：Bootstrap CSS
├── vendor_icons.html   # ⚠️ 生成物：使用中の Bootstrap Icons だけを SVG 化したもの
├── vendor_js.html      # ⚠️ 生成物：Bootstrap JS / SweetAlert2 / Chart.js / Sortable / fabric.js
│
├── package.json        # ライブラリの版を固定している（原本）
├── tools/
│   ├── build-vendor.mjs    # vendor_*.html を作る
│   ├── build-icons.mjs     # 透明を含まない apple-touch-icon を作る
│   └── verify-generated.mjs# 生成物が原本と食い違っていないか確かめる
├── scripts/
│   ├── check-project.mjs   # 品質ゲート本体（GIGA Standard v5・38項目）
│   └── lib/                # 検査ルールと PNG 透明検出
├── quality.config.json     # 品質ゲートが見るファイルの一覧
├── tests/              # 中核ロジックのテスト（node --test）
├── .github/
│   ├── workflows/ci.yml    # CI（push / pull_request / 手動）
│   └── dependabot.yml      # ライブラリ更新の自動 PR
│
└── docs/               # GitHub Pages で配るもの
    ├── index.html            # 導入案内ページ 兼 PWAシェル（URLを覚えている端末ではアプリを全画面表示）
    ├── copy-distribution.md  # 【作者向け】コピーで配るテンプレートの作り方
    ├── app.js                # シェルのロジック（CSP のため外部ファイル）
    ├── install-hook.js       # beforeinstallprompt の捕捉（head 最上部）
    ├── offline.html          # 圏外のときに出る画面
    ├── privacy.html          # プライバシーポリシー（配信物に入れる。GAS には送らない）
    ├── terms.html            # 利用規約（同上）
    ├── manifest.webmanifest  # PWAマニフェスト
    ├── sw.js                 # Service Worker
    └── icons/                # アプリアイコン
```

### ⚠️ 編集してよいファイル / してはいけないファイル

| ファイル | 編集してよいか |
|---|---|
| `code.gs` / `index.html` / `css.html` / `js_*.html` / `docs/*` | **ここを直す** |
| `package.json` / `tools/*.mjs` | **ここを直す**（ライブラリの版や組み立て方） |
| `vendor_css.html` / `vendor_icons.html` / `vendor_js.html` | **手で編集しない**（生成物） |

**原本を直したら、必ず `npm run build` を走らせてから push してください。**
忘れると、ビルドも静的解析も通るのにリポジトリの中身だけが古いまま残ります。
CI（`npm run ci`）がこの食い違いを検出して落ちます。

```bash
npm ci          # ライブラリを版どおりに入れる
npm run build   # vendor_*.html を作り直す
npm run check   # 品質ゲート（GIGA Standard v5 の検査）
npm test        # 中核ロジックのテスト
npm run ci      # 上の全部（CI と同じもの）
```

## **🚀 インストール & デプロイ手順**

このアプリはGoogle Apps Scriptとして動作します。サーバーの契約は不要です。

**先生おひとりずつが、ご自分の Google アカウントで公開して使います。**
学校をまたぐ共通の入口はありません。学習記録は、公開した先生ご自身の
Google ドライブの中だけに入り、制作者を含め、ほかの誰のところにも行きません。

入れかたは2通りあります。**A が楽です。** 学校のポリシーで外部ファイルのコピーが
禁じられている場合だけ、B を使ってください。入るものは同じです。

### **A. スプレッドシートをコピーする（おすすめ）**

1. **[スプレッドシートをコピーして始める](https://docs.google.com/spreadsheets/d/1ilyPgdjv1cRY0bDhSvNafmWfjQbKl8L98ctXy3Zhjeg/copy)** を開き、「コピーを作成」を選びます。
   > 学校のポリシーで外部ファイルのコピーが禁じられていると、ここで止まります。
   > その場合は下の B をお使いください。入るものは同じです。
2. できたファイルを開き、「拡張機能」＞「Apps Script」を開きます。
3. 下の「4. デプロイ」へ進みます（貼り付ける作業はありません）。

コピーしたスプレッドシートには、このスクリプトが束ねられています（コンテナバインド）。
**そのファイル自体がデータベース**なので、どこにデータができたのかを探す必要もありません。

### **B. ファイルを貼り付ける**

1. **プロジェクトの作成**:
   * [Google Apps Script](https://script.google.com/) にアクセスし、「新しいプロジェクト」を作成します。
2. **生成物を作る**:
   * 手元で `npm ci && npm run build` を実行します。
     `vendor_css.html` / `vendor_icons.html` / `vendor_js.html` が作られます。
     これらはライブラリ本体で、**GAS に貼るファイルに含まれます**。
3. **ファイルの作成**:
   * エディタ上で以下の **11 個** のファイルを作成し、それぞれのコードを貼り付けます。
     `code.gs` / `Gemini.gs` /
     `index.html` / `css.html` / `js_core.html` / `js_student.html` /
     `js_teacher.html` / `js_worksheet.html` / `vendor_css.html` / `vendor_icons.html` / `vendor_js.html`
   * ※ `.gs` の2つ以外は、拡張子を `.html` として作成してください。
   * ※ **`Gemini.gs` を忘れないでください。** AI でワークシートを作るところが
     `GigaGemini` を呼んでいるので、無いと**その機能だけが実行時に落ちます**
     （画面には「生成に失敗しました」としか出ません）。
   * ※ `vendor_*.html` は生成物です。GAS のエディタ上で編集しないでください。
     ライブラリを更新するときは、手元で `npm run build` し直して貼り替えます。

### **4. デプロイ**（A・B 共通）

   * 右上の「デプロイ」ボタン \> 「新しいデプロイ」を選択。
   * **種類の選択**: 「ウェブアプリ」
   * **次のユーザーとして実行**: **「自分（所有者）」**
   * **アクセスできるユーザー**: **「〈学校のドメイン〉内の全員」**
     （`example.ed.jp` のように学校のドメイン名が出ている選択肢です）
   * 「デプロイ」をクリックし、発行された **ウェブアプリURL** をコピーします。

   > **なぜこの設定なのか。** 本人確認をサーバー側で `Session.getActiveUser().getEmail()` に
   > 頼っているためです。**この組み合わせでないと、getActiveUser が実際のメールアドレスを
   > 返しません**（消費者向けアカウントや別ドメインからだと `""` になり、先生判定が働きません）。
   > 学校の Google Workspace 内での配布を前提にしてください。

### **5. 初回セットアップ**（A・B 共通）

   * **設定作業はありません。** URLを開けば、そのまま使いはじめられます。
   * **デプロイしたあなたのアカウントが、自動的に担任として登録されます。**
     ウェブアプリは「実行するユーザー: 自分」で動くため、サーバーは
     `Session.getEffectiveUser()` で**訪問者ではなくデプロイした本人**を知ることができます。
     * **誰が先にURLを開いても関係ありません。** 児童が先に開いても、
       管理者になるのはデプロイした先生です。
     * 必要な 12 枚のシートと見出しは、はじめて開かれたときにアプリが作ります。
   * デプロイ者のメールアドレスを取得できない環境（組織の制限など）でだけ、
     これまでどおり「初期設定を開始する」ボタンが出ます。この場合は先着が管理者に
     なるので、児童に配る前に先生が押してください。
   * ほかの先生を増やすには **設定（⚙）→「先生の管理（メールアドレス）」** で追加します。
   * ほかの先生を増やすには、先生モードの **設定（⚙）→「先生の管理（メールアドレス）」** で
     同僚の Google アカウントのメールアドレスを追加します。
   * AI でワークシートを生成する場合は、**設定 →「AI設定（Geminiキー・モデル）」** で API キーを登録します
     （未登録でも、手貼り HTML でワークシートは作れます）。

### **6. セットアップ状況をみる**

**スプレッドシート側で用意しておく作業はありません。** シートも見出しもアプリが作り、
名簿・単元・AI キーもすべてアプリの画面から設定できます。

いま何が整っていて何が足りないかは、**設定（⚙）＞「セットアップ状況」** で一覧できます。

| 見るもの | なぜ要るか |
|---|---|
| **ログインの確認** | ここが赤いときは**デプロイの公開設定が間違っています**。いちばん静かに壊れる箇所 |
| データベース | シートと見出しの点検結果 |
| 先生の登録 / 名簿 / 単元 / 授業配信 | 授業を始めるのに要るもの |
| AI 設定 | 未設定でも動くので任意 |

はじめかたガイド（3ステップ）は済むと消えますが、この一覧はいつでも見に来られます。

### **7. データベースの点検**

シートの並びや見出しが崩れると、ワークシートと答案が入れかわります
（どちらも**列の番号**で読み書きしているためです）。確かめる入口は2つあります。

* **スプレッドシートのメニュー**（A で入れた場合）… 上部の「みらいコンパス」＞
  「シートを点検する」／「足りないシート・見出しを直す」
* **アプリの設定**… 設定（⚙）＞「データベースの点検」

「直す」で行うのは**足すことだけ**です（シートを作る・見出し行を書く・
足りない見出しを末尾に足す）。**列の並びが入れかわっている場合は、書き換えずに
「何列目がどうずれているか」だけをお知らせします。** 見出しだけを正しくすると、
まちがった列に正しいラベルが付いて事故が見えなくなるためです。

## **📱 PWA対応（Chromeから「アプリ」としてインストール）**

本リポジトリの docs/ フォルダは、**導入案内のページ**（[mirai-compass.giga-school.com](https://mirai-compass.giga-school.com/)）であり、同時に **PWA（プログレッシブウェブアプリ）** のシェルでもあります。1枚の `index.html` が両方を兼ねていて、

* GASのURLをまだ覚えていない端末 … 導入案内のページとして読めます
* 覚えている端末 … アプリ本体が全画面で開きます（Chromebook等で専用アイコンから起動できます）

先生ごとにデプロイする形になったため、**このページからは授業を始められません**。児童は先生から配られたURLを、先生は案内の「入れかた」の手順を使います。

> **なぜシェルが必要？**
> GASのウェブアプリはGoogleのサンドボックス（iframe）内で配信されるため、GAS単体ではPWAのインストール条件（manifest / Service Worker）を満たせません。そこでGitHub Pages上に配置した軽量なシェルページがPWAとして振る舞い、その中でGAS本体を全画面表示します。アプリ本体は常にGASから最新版が読み込まれます。

### **セットアップ手順（管理者・先生）**

1. **GitHub Pagesを有効化**:
   * このリポジトリの Settings > Pages を開く
   * Source: 「Deploy from a branch」/ Branch: main / フォルダ: /docs を選択して Save
   * 数分後に `https://<ユーザー名>.github.io/MIRAI-Compass/` が公開されます

   > **配信されるのは `docs/` の中だけです。** リポジトリ直下に置いたファイルは
   > どのURLにも現れません（法務ページを直下に置いて 404 になった前例あり）。
   > 独自ドメインの `CNAME` も配信元、つまり `docs/CNAME` に置きます。
   >
   > `docs/manifest.webmanifest` の `id` / `start_url` / `scope` が `"./"` なのも
   > 同じ理由です。独自ドメイン（`https://mirai-compass.giga-school.com/`）でも
   > github.io のサブディレクトリ（`https://<ユーザー名>.github.io/MIRAI-Compass/`）でも
   > 正しく解決される唯一の書き方で、`"/"` に戻すと後者でインストールできなくなります。

2. **初期設定**:
   * 公開されたURLをChromeで開き、案内の「児童の端末に入れる」でGASのウェブアプリURL（`.../exec`）を入力して「アプリをはじめる」
3. **インストール**:
   * アドレスバー右端の「インストール」アイコン、またはChromeメニュー >「保存と共有」>「ページをアプリとしてインストール」をクリック
   * デスクトップ/シェルフにアイコンが追加され、独立ウィンドウで起動できるようになります

### **児童端末への一括配布**

URLパラメータでGASのURLを事前設定できます。以下のリンクをQRコードやクラスルームで配布すると、児童は開くだけで設定完了です。

```
https://<ユーザー名>.github.io/MIRAI-Compass/?app=<GASウェブアプリURL>
```

### **設定の変更**

* 画面**左上すみを素早く5回タップ**すると設定画面が開きます（URL変更・リセット・新しいタブで開く）
* または `?settings=1` を付けてアクセス

### **注意事項**

* 本アプリは本人確認に `Session.getActiveUser()` を使うため、GAS側のデプロイ設定は
  **「実行: 自分（所有者）／アクセス: 〈学校のドメイン〉内の全員」** が必須です。
  **「全員」も「全員（匿名ユーザーを含む）」も選ばないでください。**
  どちらもドメイン外からアクセスでき、その場合サーバーがメールアドレスを取れず
  （`getActiveUser()` が `""` を返す）、先生判定も児童の記録の結びつけも働きません。
* iframe 内ではGoogleログイン画面が開けないことがあります。表示できない時は、
  設定画面の「新しいタブで開く」から一度ログインしてください。

  * [Sortable.js](https://sortablejs.github.io/Sortable/) 1.15.0 (Drag & Drop)

  > ※ pdf.js／OCR、pako（zlib）は意図的に同梱していません（現時点で不要なため）。

> **なぜ実行コードを自己ホストするのか。**
> 学校のネットワークは `cdn.jsdelivr.net` を塞いでいることがあります。
> 塞がれた状態でこのアプリを開くと、白い画面ではなく
> **「Bootstrap が当たっていない素の HTML が半分だけ動く」**という壊れ方をしました。
> ローディング画面が消えず、`d-none` が効かないので児童画面と先生用ボタンが
> 同時に出て、`Swal` / `Chart` / `Sortable` がすべて `undefined` になります。
> 児童からは「壊れている」としか見えず、原因がアプリの外にあるので
> 先生が調べても分かりません。
>
> Google Fonts だけは外部のままにしています。届かなくても**字の形が変わるだけ**で
> アプリは動くからです（`css.html` で端末側の日本語フォントを後ろに並べてあります）。
> 日本語フォントを自己ホストすると初回転送が数MBになり、
> 校内Wi-Fiで40人が同時に開くという、いちばん避けたい状況を自分で作ります。

## **🗄 データの持ち方（スプレッドシート12枚）**

「初期設定を開始する」を押すと、実行した先生の Google ドライブに**スプレッドシートが1つ**作られ、
その中に次の12シートが自動生成されます（列が足りなければ、次回アクセス時に自動で足されます。
定義は `code.gs` の `DB_SCHEMA`）。

| シート | 何が入るか |
|---|---|
| `UnitMaster` | 単元と課題の定義（カテゴリ・実施回・必修/選択・先生主導/個別・所要時間・前提課題） |
| `StudentRoster` | 名簿（クラス・出席番号・氏名・在籍・**メールアドレス（任意）**） |
| `ClassSchedule` | 授業配信（日付・時刻・単元・時数・メッセージ） |
| `StudentPlans` | 児童が立てた学習計画 |
| `MyTasks` | 児童が自分で作った課題 |
| `LearningLogs` | 「できた！」などの学習ログ |
| `LiveStatus` | いまの状態（現在の課題・SOS/集中・座席の座標） |
| `DailyReflections` | 毎時間のふりかえり（達成度・コメント・発揮した力） |
| `Portfolios` | 単元のまとめと、先生のコメント・スタンプ |
| `Feedback` | 課題ごとに先生が送ったスタンプ |
| `Worksheets` | ワークシート本体（HTML・下地キャンバス・ルーブリック・公開設定） |
| `Responses` | 児童の回答（入力・手書き・提出状態・先生の赤ペン・公開/リアクション） |

児童のデータは**正準キー**でまとめます。本人の Google メール（`studentId`）が分かる行はそれを、
分からない古い行だけ `name:表示名` を使います。名簿にメールを入れておくと、同名児童がいても
記録が混ざりません。

## **🔒 セキュリティ設計と、いま分かっている課題**

| 項目 | 状態 |
|---|---|
| 本人確認 | サーバーが `Session.getActiveUser().getEmail()` で**呼び出し元を自分で判定**。クライアントから ID を受け取らない |
| 先生の権限 | メールアドレスの**許可リスト**（`TEACHER_EMAILS`／ScriptProperties）。初期設定を実行した人が最初の先生。以後は「先生の管理」で追加 |
| パスワード | **廃止**（`TEACHER_PASS` / `verifyPassword` は削除済み） |
| 秘密情報 | Gemini API キー等は `PropertiesService`（スクリプトプロパティ）に保存。コードに直書きせず、クライアントにも返さない |
| 排他制御 | 書き込み系関数は `LockService` + `try...finally` |
| CSP | `docs/` シェルには適用済み（`script-src 'self'`、インライン無し）。GAS 本体は後述 |
| 外部からの実行コード | 0 バイト |

### 教員用 API の本人確認（getActiveUser 方式）

教員向け関数（`saveWorksheetToDB` / `saveFeedback` / `createWorksheetsForUnit` /
`saveClassRoster` / `deleteUnitTask` など）は、`google.script.run` から直接呼べても、
**サーバー本文の先頭で `MiraiAuth.requireTeacher()` が呼び出し元のメールを許可リストと
照合します。** 画面側の出し分けは防御ではありません（品質ゲートの `SEC_PRIVILEGED_FN_GUARDED`
がこのガードの有無を機械的に検査し、`SEC_NO_PASSWORD_AUTH` がパスワード認証の復活を防ぎます）。

> この方式は、デプロイを **「実行: 自分／アクセス: 〈学校のドメイン〉内の全員」** にして初めて成立します
> （`getActiveUser` が実メールを返す条件）。消費者向けアカウントでは空文字が返るため、
> Workspace 配布が前提です。

### 🟡 残っている課題（正直な現状）

- **児童テーブルの ID 化: 完了（Ver 3 で正準キーに統一）**: 児童の自己書き込み
  （`LearningLogs` / `StudentPlans` / `DailyReflections` / `Portfolios` / `MyTasks` / `Responses`）は
  本人メール（`studentId`）をキーに読み書きします。先生向けの全集計
  （進捗一覧・まとめ・LIVE・ギャラリー）も**正準キー**（本人メール優先、不明な行のみ
  `name:表示名` フォールバック）でまとめるため、同名児童のデータが混ざりません。
  タスクスタンプ（`Feedback`）は本人IDつきで保存され、児童側は「IDがある行はIDでだけ照合」します。
  名簿には**メール列（任意）**が追加され、入力しておくと名簿と記録が完全に一致します
  （空欄でも動作。名簿保存時に同名の在籍児童は具体名つきで警告）。

  > **⚠️ Ver 2 からの移行**: `StudentRoster` に `studentId` 列が追加されました。
  > シート構造は初回アクセス時に自動補修されますが、**旧バージョンのデータを引き継がず
  > シートを削除して作り直す**のがもっとも確実です（アプリの「初期設定」から再作成できます）。
- **統合時に先送りしていた3つは、いずれも実装済みです**（過去の README にあった「未実装」は解消）。
  児童の相互閲覧は「ひろば」（`getSharedResponses` / `savePeerReaction`）と「みんなの計画」、
  ワークシートの一括管理画面は先生の「添削」ビュー（`getDashboardData` / `generateBatchComments` /
  `batchSaveFeedback`）、下部4タブナビは `STUDENT_NAV_TABS` として入っています。
- **サーバーにあるが画面から呼んでいない関数**: `archiveUnitData`（単元データの退避）と `getHistory` は
  クライアントから呼び出していません。GAS エディタから手で実行することはできますが、UI はありません。
- **実機・本番未検証**: `getActiveUser` の実際の戻り値、40人同時アクセス、実端末、印刷結果、
  `gigayama.github.io` での PWA 動作は、ビルド環境から `script.google.com` に到達できないため
  未確認です。詳細は `AUDIT.md` の統合完了セクションを参照してください。

### GAS 本体に CSP を入れていない理由

GAS は `.gs` と `.html` しか置けず、JavaScript は `include()` でインラインの
`<script>` として埋め込まれます。つまり **`script-src 'self'` は構造上成立しません。**
`'unsafe-inline'` を足せば入れられますが、それでは CSP を入れた意味がほとんど
無くなります。代わりに、**外部から読む実行コードを 0 にする**ことで
攻撃面を減らしました。`docs/` シェル側には本物の CSP が入っています。

## **🤝 ワークシート機能について（旧「みらいパスポート」の統合）**

以前は別アプリだった **みらいパスポート**（AIワークシートの作成・提出・添削）は、
**このプロジェクトに取り込まれ、内部機能になりました。** 別 GAS プロジェクト・別ログイン・
アプリ間連携（ImportQueue への直書き、`doPost` Webhook、起動用 URL 受け渡し）は**すべて廃止**され、
ワークシートの作成・回答・添削はこのアプリ内の関数呼び出しで完結します。

* **作成**: 先生が単元のタスクから作ります（単元設計画面の「**WS作成**」ボタンで単元の全タスク分を
  まとめて用意 → `createWorksheetsForUnit`。1つだけ作り込むときはタスク編集の
  「**ワークシート作成・編集**」）。中身は Gemini による自動生成か、手貼りの HTML です。
* **配布**: 特別な操作はありません。作ったワークシートはそのタスクに自動でひも付きます。
* **回答**: 児童はタスクを開くと、その場でワークシートが開きます（入力＋手書き。
  ローカル自動保存つき）。「公開」をオンにして提出すると「ひろば」に載ります。
* **添削**: 先生が赤ペンで添削して返却し、児童は「先生コメント」を受け取ります。
  提出物一覧からは **AI一括コメント**で全員分の下書きを作り、確認してから一括返却できます。

> **別アプリの「みらいパスポート」は、この統合プロジェクトに置き換えられました（役割を終えています）。**
> 統合の設計・経緯は `INTEGRATION.md` を参照してください。
